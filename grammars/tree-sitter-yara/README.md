# tree-sitter-yara

A [Tree-sitter](https://tree-sitter.github.io/) grammar for the
[YARA](https://virustotal.github.io/yara/) rule language, with highlight
queries in nvim-treesitter's capture style. It was written for
[Treelights](../../), a code-highlighting plugin for Obsidian, and is
designed to be used on its own by Neovim, Zed, Helix or any other
Tree-sitter host.

Designed and directed by James Pearson. The grammar, queries, tests and
this README were generated with AI assistance (Claude), working from the
official YARA documentation, and tested as described below.

## Why a new grammar

The existing community YARA grammars could not parse common syntax such
as hex jumps (`[2-4]`), `$a at 0`, string sets (`($s*)`) and match counts
(`#a`), and they come from single maintainers whose code would have had to
be trusted. This grammar was written from scratch from the language
documentation, so nothing in it comes from an unreviewed source:

- **No external scanner.** There is no hand-written C. Everything that
  runs is generated by Tree-sitter from `grammar.js`, which is short
  enough (about 370 lines) to read in one sitting.
- **Verifiable generated code.** Running `tree-sitter generate` on
  `grammar.js` reproduces `src/` exactly; Treelights' build checks this
  every time and stops if they differ.

## What it covers

YARA 4.x syntax:

- `import` and `include`; `private` and `global` rules; tags
- `meta` values: strings, integers (including negative), booleans
- strings: text strings with escapes, hex strings (wildcards including
  nibbles, `~` negation, jumps `[n]`, `[n-m]`, `[n-]`, `[-]`,
  alternatives, comments inside), regular expressions with `i` and `s`
  flags, anonymous `$` and `$_` strings
- modifiers: `nocase`, `wide`, `ascii`, `fullword`, `private`, `xor`,
  `xor(n)`, `xor(n-m)`, `base64`, `base64wide` and custom alphabets
- conditions, with YARA's operator precedence: `and`, `or`, `not`,
  `defined`; comparisons; string operators (`contains`, `icontains`,
  `startswith`, `istartswith`, `endswith`, `iendswith`, `iequals`,
  `matches`); arithmetic (`\` is division) and bitwise operators
- `#a`, `@a[i]`, `!a[i]`, `$a at x`, `$a in (x..y)`, `#a in (x..y)`
- `of` with string sets, rule sets, `them`, percentages (`50% of them`)
  and `at`/`in`; `for … of`, `for … in` over ranges, enumerations and
  module iterables; `with` declarations
- modules (`pe.sections[0].name`), function calls, integer reads
  (`uint32be(0)`), `filesize`, `entrypoint`, `KB`/`MB` sizes, hex and
  octal integers, floats

It parses syntax; it does not check meaning (for example, that a string
named in a condition is defined).

## Testing

`test/corpus/` holds 23 test cases covering every feature above. Each
expected tree was reviewed line by line for correct structure and
operator precedence:

```sh
tree-sitter test
```

The grammar was also run over three public rule collections (November
2026), and every file parsed without errors: 1,630 files holding about
20,000 rules.

- [ReversingLabs YARA rules](https://github.com/reversinglabs/reversinglabs-yara-rules)
  at `e0a0be5`: 310 files
- [Yara-Rules](https://github.com/Yara-Rules/rules) at `0f93570`: 566
  files
- [signature-base](https://github.com/Neo23x0/signature-base) at
  `de3c725`: 754 files

To repeat it, clone a collection and run:

```sh
find <folder> -name '*.yar' -o -name '*.yara' > files.txt
tree-sitter parse --quiet --stat --paths files.txt
```

## Highlighting

`queries/highlights.scm` uses nvim-treesitter's capture names: rule names
as functions, tags as labels, meta keys as properties, string names
(`$a`, `#a`, `@a`, `!a`) as parameters, modifiers as attributes, hex
wildcards, negations and jumps like escape sequences, and `uint32()`-style
reads as built-in functions. `queries/injections.scm` hands comments to the
`comment` grammar.
